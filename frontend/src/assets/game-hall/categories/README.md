# 官方游戏分类视觉规范

这套规范用于游戏大厅一级入口中的“游戏分类”卡片。分类视觉负责表达一组玩法，不是某个具体游戏的图标；点击分类后，用户才进入该分类的游戏列表。

分类卡片必须与单个游戏卡片有明确层级差异，同时继续使用同一套产品材质语言：**克制的赛博界面骨架 + Apple 产品级 2.5D 游戏物件**。

## 1. 资源策略

分类视觉默认不制作独立位图，也不复制游戏图标资源。它由以下内容在界面中实时组合：

- 1–3 个已有官方游戏图标；
- 分类专属的低饱和色调；
- 轨道、信号线、编号等轻量界面结构；
- 分类名称、说明、游戏数量与实时房间数量。

这样可以保证分类与内部游戏身份一致，也避免每次调整游戏图标后维护另一套重复素材。

只有在组合式视觉无法清楚表达分类时，才允许新增分类专属图片。新增前必须先说明无法复用的原因，并保持本规范中的画幅、安全区和三主题规则。

## 2. 与游戏图标的区别

| 项目 | 分类视觉 | 单个游戏图标 |
| --- | --- | --- |
| 语义 | 一组玩法的入口 | 一个具体游戏 |
| 画幅 | 横向卡片中的组合场景 | 1:1 方形产品图标 |
| 主体 | 1–3 个代表游戏物件 | 一个游戏的核心识别物 |
| 信息 | 分类名、描述、数量、状态 | 游戏名与简短玩法信息 |
| 交互层级 | 一级入口 | 二级具体选择 |
| 资源来源 | 复用游戏图标并由 CSS 编排 | `icons/<game-slug>-{dark,light}.webp` |

禁止把分类入口制作成放大的单游戏卡片，也禁止用一个游戏的主体独占整个分类视觉。

## 3. 布局规格

分类总览使用 Bento 网格，但所有卡片属于同一层级；`wide` 和 `standard` 只表示占用宽度，不表示重要性或推荐顺序。

### 电脑端

- `wide`：占据较宽网格列，适合包含 3 个代表图标的分类。
- `standard`：占据标准网格列，适合包含 1–3 个代表图标的分类。
- 卡片最小高度：230px。
- 卡片内容区由“文案区 + 横向视觉区”组成，视觉区最小高度 188px。
- 默认文案区与视觉区比例约为 45:55；不得为了放大图标压缩标题和描述。

### 手机端

- 所有分类按单列排列，不保留桌面端跨列关系。
- 卡片最小高度：148px；视觉区最小高度 118px。
- 文案区与视觉区比例约为 54:46。
- 小于 380px 时可以隐藏描述，但分类名称、游戏数量和进入意图必须保留。
- 页面和卡片不得产生横向滚动；交互热区不得小于 44px。

### 安全区

- 组合图标不得覆盖标题、数量、房间状态和进入按钮。
- 卡片外侧 8% 为裁切危险区，核心识别物不得完全落入该区域。
- 图标可以局部错层，但每个代表游戏至少保留一个完整、可识别的核心轮廓。
- 编号、轨道和信号线只能作为背景，不得比代表游戏物件更醒目。

## 4. 组合规则

### 三个代表图标

- 左、右两个图标位于下层，允许向卡片边缘轻微溢出。
- 中间图标位于上层并略小，形成稳定三角构图。
- 图标旋转控制在 `-9°` 到 `9°`，避免杂乱或卡通化。

### 两个代表图标

- 使用左右错层构图，两个主体大小接近。
- 不以颜色区分主次，依靠前后层级和轮廓形成节奏。

### 一个代表图标

- 图标可放大，但不得伪装成单游戏入口。
- 必须保留分类标题、游戏数量、横向场景和分类结构元素。
- 当分类增加新游戏时，应及时升级为两个或三个代表图标。

分类最多展示 3 个代表图标。更多游戏通过数量和分类详情表达，不得把所有游戏缩小后堆在一张卡片里。

## 5. 代表游戏选择

代表图标写在 `frontend/src/gameCategories.ts` 的 `artworkKeys` 中。选择顺序如下：

1. 优先选择能代表分类核心玩法的游戏。
2. 主动拉开轮廓，避免三个方板、三个圆盘或三组扑克牌并排。
3. 优先覆盖不同材质高度：低平棋盘、竖向装置、圆形仪表等。
4. 不按热度、推荐位或房间数量动态替换，避免分类身份频繁变化。
5. 新增游戏不等于必须修改代表图标；只有分类识别发生实质变化时才调整。

当前配置：

| 分类 ID | 中文名称 | 布局 | 代表图标 |
| --- | --- | --- | --- |
| `board` | 棋类竞技 | `wide` | 围棋、国际象棋、中国象棋 |
| `social` | 推理社交 | `wide` | 阿瓦隆、无间疑云、一夜狼人 |
| `cards` | 扑克牌类 | `standard` | 德州扑克、斗地主 |
| `solo` | 单人挑战 | `standard` | 临界穿越、深井、扫雷 |
| `party` | 派对经营 | `standard` | 地产大亨 |

## 6. 分类色调

每个分类只使用一个低饱和辅助色。它用于细边框、状态点、信号线和极弱环境光，不改变游戏图标自身材质。

| 分类 | 色彩方向 | 当前基准色 |
| --- | --- | --- |
| 棋类竞技 | 青玉灰绿 | `#719b8a` |
| 推理社交 | 冷灰紫 | `#8a7ca6` |
| 扑克牌类 | 暗珊瑚红 | `#a97579` |
| 单人挑战 | 冰青灰 | `#6f9da2` |
| 派对经营 | 香槟砂金 | `#a78e64` |

辅助色不能铺满背景，不能形成强霓虹外发光，也不能成为识别分类的唯一方式。

## 7. 三套主题

三套主题共享完全一致的分类、构图、图标数量、顺序和交互。只允许通过主题令牌切换材质、明暗与图标变体。

### 极光雾舱（`emerald`）

- 深空灰黑钛骨架、分层烟熏玻璃和冷银边缘。
- 使用游戏图标的 `dark` 变体。
- 冰蓝、靛蓝、青绿仅作为低饱和折射和仪表光。
- 保持暗部层次，禁止大面积纯黑和强烈霓虹。

### 暖钛陶瓷（`midnight`）

- 黑钛底盘、深石墨陶瓷、暖灰玻璃和香槟金属。
- 使用游戏图标的 `dark` 变体。
- 高光柔和、接触阴影明确，不能变成金色奢华或仿古风格。

### 月白陶瓷（`royal`）

- 月白陶瓷、乳雾玻璃、自然铝和冷灰环境光。
- 使用游戏图标的 `light` 变体。
- 文字、按钮和状态在浅色表面必须保持清晰边界。
- 禁止低对比度白字、透明度过高的按钮文字和纯白扁平卡片。

## 8. 文案规则

- 分类名称使用 2–6 个汉字，表达玩法范围，不使用营销口号。
- 眉题使用两个并列概念，例如“布局 · 计算”。
- 描述说明该类游戏共同的决策体验，不罗列全部游戏。
- 卡片最多展示前 3 个游戏名称，其余通过“共 N 款游戏”表达。
- “实时房间”只显示真实数据；没有房间时使用“浏览游戏”，不得伪造热度。

## 9. 新增分类流程

1. 在 `OfficialGameCategoryId` 增加稳定的英文 ID。
2. 在 `CATEGORY_DEFINITIONS` 增加分类定义、全部 `gameKeys` 与 1–3 个 `artworkKeys`。
3. 为分类设置一个低饱和 `--category-tone`，不得复用另一个分类的唯一色相。
4. 根据内容密度选择 `wide` 或 `standard`；不要用布局表达商业优先级。
5. 补充 `gameCategories.test.ts`，确保没有漏分、重分或引用未注册游戏。
6. 在三套主题下分别检查电脑端与手机端。
7. 同步更新本 README 的当前配置表。

## 10. 验收清单

提交分类视觉前必须全部通过：

1. 分类是一级入口，点击后进入该分类的具体游戏列表。
2. 所有已注册官方游戏恰好属于一个分类，没有漏分或重复。
3. 分类卡片明显是横向组合视觉，不会与方形单游戏图标混淆。
4. 代表图标不超过 3 个，且在 390px 手机宽度下仍可辨认。
5. `wide` 与 `standard` 视觉重量接近，不形成错误的推荐等级。
6. 极光雾舱、暖钛陶瓷使用 `dark` 图标，月白陶瓷使用 `light` 图标。
7. 月白陶瓷中标题、描述、数量、按钮文字和禁用态均清晰可读。
8. 320–430px 手机宽度无横向溢出，触控区域不小于 44px。
9. 桌面端常用宽度下没有标题异常换行、图标遮字或卡片高度跳动。
10. 无人物、强霓虹、电竞盾牌、奇幻徽章、卡通边框、金币、Apple 标志和水印。
