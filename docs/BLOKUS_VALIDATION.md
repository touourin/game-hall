# 四人方格接入与验收

## 改动范围

社区子模块的 `plugin-blokus` 提供四人方格游戏：20×20 棋盘，每人相同的 21 块棋块、89 个单位格；分别从四个角开始，后续同色只能角接，不能边接。包含完整棋块库、旋转和翻转、落点预览、手机棋盘缩放、规则说明及深浅两套图标。

主项目增加通用 `ranking` 成绩类型。单局名次分为 **+2 / +1 / 0 / −1**，保留 0 和负数，个人战绩展示名次与分数，排行榜按累计积分排序。复用现有有符号 `score_value` 字段，不需要数据库迁移。含游客的对局沿用平台政策，不写入任何参与者的战绩。

按剩余单位格数从少到多排名；相同时比较剩余块数，再比较本局行动顺序（后行动者优先）。这是为了提供四个独立名次的大厅规则，不使用经典版放完棋块的奖励分。

四人准备后再来一局时，游戏直接使用大厅轮换后的座位分配颜色和起始角，不重新随机或固定房主先手。

## 本地真实联机验收

经用户授权，在独立 SQLite 测试库创建恰好四个测试账号，通过真实 HTTP / Socket.IO 会话运行，不注入房间状态或绕过认证。

- 完成三局自然终局，分别为 70、63、70 次合法落子。其中 63 步的一局由实际浏览器控制一位玩家，其余三位由测试客户端操作；修复续局问题后重跑了 70 步的完整对局。
- 实际页面验证了创建房间、四人到齐、从四角开始、选择棋块、旋转、翻转、非法落点禁用确认、查找合法位置、消耗库存、自动跳过和四人排名。
- 真实连接检查了非当前玩家操作、错误起始角、同色边接、缺少角接、越界、重叠、已用棋块、旧回合编号及非法参数的拒绝，且棋盘不被修改。
- 中盘断开并恢复测试客户端，座位、回合、棋盘保持不变；使用其他账号的恢复令牌不能占用其座位。浏览器刷新同样恢复对局。
- 手机宽度 390px 下页面无横向溢出；棋盘放大至 600px 时只在棋盘容器内滚动。桌面宽度 1440px 下布局正常。
- 在真实页面重现并修正了续局重复分配先手的问题。修复后，大厅第一座位与蓝色左上角一致，上一局房主轮换到绿色左下角。
- 另验证续局、提前弃权、保留已落棋块，以及四个名次分的保存。实际战绩详情与排行榜正确显示 0 和负分，多局累计与单局记录一致。

本地测试账号、密码、会话、SQLite 文件、截图和运行日志不提交到仓库。此验收使用本地 SQLite，未部署到远端，也未执行生产 MySQL / Redis 环境验收。

## 配套集成

本改动涉及主项目与社区子模块两份 PR，应配套审查。建议先合并社区游戏 PR，再合并主项目 PR；主项目通过子模块提交指针启用游戏及对应的 `ranking` 支持。

初始化社区子模块后，在主项目根目录可用以下命令检查：

```sh
python -m pytest backend/tests
python scripts/test_community_games.py
npm --prefix frontend run test:run
npm --prefix frontend run build
```

前端时钟测试需使用 `Asia/Shanghai` 时区运行；Windows 的既有测试限制见上文。
